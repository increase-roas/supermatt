# Target adoption contract

Read this for requests such as "do the Muse pass on Hermes using that wiki" or "use that wiki to improve Cursor". Resolve the target from the user's existing workspace/profile and authoritative runtime, not a product-name guess. Use the current tool card and platform docs when a mechanism is uncertain.

## One saved contract

Extend the existing mission plan. Record only what changes execution:

- Source: exact wiki/repository/package IDs, version or current-as date, immutable snapshot/hash manifest, and separate inventories for product pages and procedure packages.
- Target: agent, host, selected profile/workspace, runtime version, canonical owner paths, actual loaded/distributed copies, supported save/reload route.
- Authority: inspect/recommend versus implement, latest exclusions, identity and existing permission rules to preserve.
- Capabilities: native tools and dependencies actually available; verification, fresh-context execution, and artifact retrieval routes. A tool named in a source is not installed evidence.
- Finish: every source item dispositioned, useful changes landed, affected pointers repaired, same-input checks, report reopened, remote readback where claimed.

### Hermes target

Resolve the exact existing profile and its host before touching files. Inspect that installed version's loader and supported skill layout, profile-scoped instructions/memory, managed metadata, and gateway/session reload behavior. Separate local desktop, CLI, remote service, and other profiles. Use native tools and fresh sessions available there; report the independence gap if no fresh context exists. A Mac-side package is preparation until the chosen Hermes profile discovers and uses it. This section is a discovery checklist, not a claim about a specific Hermes version or fixed home path.

### Cursor target

Determine whether the requested scope is one repository or the user's global Cursor setup. Inspect effective project/ancestor rules, native skill/plugin discovery, and canonical sources before edits. Use Cursor's supported native formats and refresh route. Preserve app settings and unrelated repositories; do not enable Claude imports or copy Codex's global instructions to make a skill visible. A local rule file or skill link establishes configuration only; verify selection in a fresh Cursor context before claiming observed behavior. No UI-only or CLI-only check proves both surfaces.

### Other targets

Follow the same contract using native owners. Muse's catalogue/YAML, Library paths, and managed self-improvement loop were facts of that runtime, not defaults for another agent. Never transfer source-author hardware, business facts, personality, accounts, or identity references as facts about Alex.

## Coverage record and faster repeat runs

Keep one machine-readable manifest beside the plan, using the source's existing exporter/hash format where available. Each item needs its stable source ID/path, content hash or revision, kind, disposition, target owner, adaptation/dependency reason, and check/evidence status. Dispositions: adopted, adopted subset, already covered, reference/inapplicable, or blocked with a concrete cause. Preserve source snapshots unchanged and back up existing target owners before writes.

Reconcile exact source IDs against disposition IDs: missing, duplicate, and unexpected items must be listed. Compute totals from rows, never prose. Keep wiki pages, packages, installed owners, and native help files as separate counts. A README can contain a useful procedure; classify by content rather than filename.

On a repeat run, refresh the source index and target contract first. Compare hashes/revisions with the saved manifest. Reuse unchanged dispositions only while their owner, target capabilities, scope, and evidence remain applicable. Read changed/new items and affected references; recheck previously blocked items if the missing capability changed. Preserve removed-source history. Read omitted/unhashed sources rather than calling them unchanged. Update the complete accounting while testing only changed behavior and unresolved concerns. This saves rediscovery without dropping coverage.

## Behavioral acceptance and delivery

Capture the actual pre-change miss on a harmless representative input, then rerun the same input after adaptation. Use fresh target contexts where possible. Include an ordinary positive trigger, a nearby negative, a contextual omission follow-up, and explicit recommend-only narrowing. Pressure that changes no scope should preserve the task; a later explicit scope change wins. Keep expected answers out of selection-test prompts.

Exercise a small useful output for an adopted capability or merge. Distinguish procedure selection from execution: routing success, rendered output, live write/readback, offline behavior, and automatic future learning each need their own evidence. A parent simulation does not establish native target operation. If tools are missing, finish independent useful work and retain an exact unproven item; do not replace it with a confident claim.

Reopen the final artifact from the user's normal retrieval path. Store the manifest, full changed owner files or diff, backups, checks, and limits with the same report. Preserve original file bytes when fixing findability; a catalogue wrapper may point to an existing artifact without regenerating it. Keep secrets and client data out of portable bundles.
